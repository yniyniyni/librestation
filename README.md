# librestation (max)

Яндекс Станция Макс без Яндекса: Spotify Connect, голосовые команды, голосовой
ассистент и своя индикация на кольце и экране. Быстрые команды (пауза, дальше,
громче…) работают прямо на колонке, без триггера и без сети. Ассистенту сеть нужна:
после слова-триггера фраза уходит в Google Gemini Live, который вызывает инструменты
(Spotify Web API, громкость и управление плеером, погода, время, короткие ответы
через Google Search) и отвечает низколатентным голосом.

*Yandex Station Max (rooted, Android 9) turned into a Spotify Connect speaker with
on-device voice commands, a Gemini-powered voice assistant (cloud: the phrase after
the trigger word goes to Google; quick commands stay fully local) and its own LED
ring/screen UI. Docs are in Russian.*

> Неофициальный проект. Не связан с Яндексом или Spotify. Нужна рутованная
> колонка; всё, что здесь описано, вы делаете на свой страх и риск.

## Важно: поддерживаемый способ root

Колонка **изначально должна быть рутована** и иметь:

- ADB по сети;
- команду `mysudo`, через которую доступен root.

У `mysudo` две особенности, которые учитывают все скрипты проекта: ему нужен
терминал (`adb shell -tt`), и он режет команду по пробелам, так что
`mysudo sh -c "a b"` выполнит только `sh -c a`. Простая команда с аргументами
проходит (`mysudo -n pm uninstall …`), а составную нужно положить в скрипт на
колонке и запустить `mysudo -n sh /path/script.sh`. Код возврата `mysudo` всегда 0.
Если колонка рутована другим способом, установщик придётся адаптировать.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| Spotify Connect | `soloist/` | Официальный Spotify Soloist в Debian-chroot → PulseAudio (float) → FIFO → `aaudio_pipe` → audioserver. Сервис поднимает и перезапускает всё сам и держит кэш Soloist в пределах 300 МБ. |
| `aaudio_pipe` | `aaudio-pipe/` | Мост FIFO → AAudio (NDK, C). Компенсирует программную громкость Soloist, чтобы громкостью управлял усилитель. |
| `voiced` | `voice/cmd/voiced` | Локальные голосовые команды, обучение на голосе пользователя, эхоподавление, единая громкость и веб-панель. |
| Ассистент | `voice/internal/assistant`, `agent`, `tools`, `tts`, `spotifyapi`, `geminilive` | Слово-триггер → фраза в Gemini Live → инструменты (Spotify Web API, плеер и громкость, погода, время, Google Search) → потоковый голосовой ответ. Работает внутри `voiced`; старый агент и TTS/Piper остаются запасным путём. |
| `ledd` | `voice/cmd/ledd` | Часы, спектр музыки, громкость и реакция на команды для кольца и экрана. |
| `setup` | `setup`, `voice/cmd/setup` | Установка по шагам и проверка работающей колонки (`./setup doctor`). |

Дизайн и решения — в `docs/`: голосовые команды
([docs/2026-10-29-voice-commands-design.md](docs/2026-10-29-voice-commands-design.md)),
кольцо и экран ([docs/2026-10-29-led-ui-design.md](docs/2026-10-29-led-ui-design.md)),
ассистент ([docs/2026-10-31-assistant-design.md](docs/2026-10-31-assistant-design.md)),

## Что нужно

### Колонка

- Яндекс Станция Макс (`yandexstation_2`) на Android 9.
- Root через `mysudo` и ADB по сети.
- Около 1,7 ГБ свободного места на `/data`: rootfs занимает ~1,5 ГБ, остальное —
  кэш Soloist (до 300 МБ), модели, записи и логи.
- Подготовленный Debian rootfs для `linux/aarch64` с PulseAudio (`rootfs.tar.xz`;
  с уже работающей колонки его снимает `./setup export-rootfs`, см. ниже).
- Сборка Spotify Soloist для `linux/aarch64` и **свой** developer API key Soloist.
  Soloist и ключ в репозитории не распространяются.
- Прокси, если Spotify без него недоступен: на роутере или Xray прямо на колонке
  (его ставит `./setup`).

### Компьютер для сборки

Поддерживаются macOS и Linux:

- Go 1.24 или совместимый Go, умеющий собирать `linux/arm64`;
- Java `javac`;
- Android SDK с платформой `android-28` и `d8` из build-tools;
- Android NDK с `aarch64-linux-android28-clang`;
- `adb`, `python3`, `xz`/обычные Unix-утилиты.

По умолчанию на macOS скрипты ищут SDK в `$HOME/Library/Android/sdk`.
На Linux задайте `ANDROID_SDK` явно. Пути можно переопределить переменными
окружения; сами скрипты больше не требуют фиксированного расположения NDK.

## Установка

Из корня репозитория:

```sh
./setup
```

Установщик проходит по шагам и каждый сначала проверяет, поэтому его можно
запускать сколько угодно раз: на новой колонке он ставит всё, на работающей —
только предлагает обновиться. Колонку он возьмёт из `-device <ip>` или
`ADB_DEVICE`, а если их нет — спросит IP или найдёт её в сети по adb-порту.

Шаги:

1. инструменты на компьютере (adb, Go, javac, python3, Android SDK и NDK);
2. root на колонке и свободное место;
3. сборка и заливка `voiced`, `ledd`, `aaudio_pipe` и скриптов (`voice/deploy.sh`);
4. Debian rootfs с PulseAudio — спросит путь к `rootfs.tar.xz` (если архив лежит
   в корне репозитория, предложит его сам);
5. Spotify Soloist — спросит путь к бинарнику `linux/aarch64`;
6. ключ Soloist и, по желанию, ключ Gemini — ввод скрытый, ключи хранятся
   только на колонке;
7. прокси — на роутере (на колонке ничего не ставится) или Xray на колонке;
8. автозапуск в `/data/local/tmp/myscript-max.sh` (загрузочный скрипт рута);
9. отвязка от Яндекса (см. ниже) и уборка файлов старых версий;
10. кэш Soloist, запуск сервисов, веб-панель и микрофон;
11. модель Gemini, если есть ключ;
12. «Запасной голос Piper» — скачивает Piper и голос ru_RU irina medium (~90 МБ,
    хеши проверяются) в rootfs;
13. «Spotify Web API» — привязка Spotify для ассистента (см. ниже).

Проверить работающую колонку, ничего не меняя:

```sh
./setup doctor
```

Без терминала (`./setup < /dev/null`, CI) установщик тоже только проверяет.
Rootfs, Soloist и ключи в репозиторий не входят, их нужно получить отдельно.

**Rootfs для другой колонки.** На колонке, где всё уже работает:

```sh
./setup export-rootfs            # или -o путь/к/rootfs.tar.xz
```

Сервисы останавливаются на время упаковки и потом запускаются снова. В архив не
попадают ключи Soloist и Gemini, `xray.json`, вход и кэш Soloist, бинарники Soloist
и Xray, `resolv.conf` и `/root/.config`: на время tar они убираются из rootfs и
возвращаются обратно, а готовый архив ещё раз проверяется на ключи и данные
прокси с этой колонки. Нужно столько же свободного места на `/data`, сколько
занимает rootfs. Получившийся `rootfs.tar.xz` кладут в корень репозитория на
другом компьютере — шаг 4 `./setup` возьмёт его сам.

**Прокси.** Если Spotify (или Gemini) без прокси недоступен, есть два варианта:

- **на роутере** — на колонке ничего не ставится, `./setup` только запоминает выбор;
- **Xray на колонке** — `./setup` скачивает последний релиз
  [Xray-core](https://github.com/XTLS/Xray-core) для arm64, сверяет его SHA-256 с
  `.dgst` релиза и кладёт в rootfs (`/opt/xray`). Настройки — VLESS-ссылка
  (`vless://…`, ввод скрыт; поддерживаются tcp/ws/grpc/xhttp/httpupgrade с tls или
  reality), из которой собирается `xray.json`, или ваш готовый `xray.json`. Он
  хранится только на колонке (`/data/local/tmp/soloist/xray.json`, права 600) и
  должен слушать socks на `127.0.0.1:1080` и http на `127.0.0.1:1081`: через них
  ходят Soloist и `voiced`. Частные адреса идут напрямую.

Обновить только программы после изменений в коде:

```sh
ADB_DEVICE=<ip>:5555 sh voice/deploy.sh
```

`deploy.sh` сервисы не перезапускает: после заливки перезапустите их вручную
(`stop.sh`, затем `start.sh`, команды ниже). Сейчас `stop.sh` не останавливает
`ledd`, его нужно завершить отдельно.

Управлять сервисами вручную:

```sh
adb -s "$ADB_DEVICE" shell -tt 'mysudo -n sh /data/local/tmp/soloist/start.sh'
adb -s "$ADB_DEVICE" shell -tt 'mysudo -n sh /data/local/tmp/soloist/stop.sh'
adb -s "$ADB_DEVICE" shell -tt 'mysudo -n tail -50 /data/local/tmp/soloist/soloist.log'
```

## Ассистент

Быстрые команды (пауза, дальше, громче…) выполняются локально: без триггера, без
сети, всё слушание на колонке и никуда не уходит. Ассистенту нужна сеть.

Триггер — любое записанное слово, которому в панели назначено действие
«ассистент». Дальше свободная фраза («включи The Weeknd», «лайкни трек», «погода
в Праге»). После ответа колонка ещё ~5 с слушает без триггера (уточнение).
Если сказать триггер, пока она говорит, она замолчит и выслушает вас.

Что умеет Gemini через инструменты:

- Spotify Web API: включить артиста, трек, альбом или плейлист; лайк и снятие
  лайка с текущего трека; «что играет»;
- пауза, дальше, назад и громкость;
- погода (Open-Meteo, город по умолчанию задаётся в панели);
- время и дата;
- короткие ответы на общие вопросы через Google Search.

**Что уходит в Google:** аудио фразы после триггера и уточнений передаётся в Gemini Live;
вызовы инструментов выполняются локально, а их результаты возвращаются модели.
Быстрые команды и постоянное прослушивание никуда не отправляются. Ключ и прокси те
же, что у проверки срабатываний.

**Быстрые команды Яндекса.** Слова «стоп», «хватит», «пауза», «дальше»,
«следующий», «назад», «громче», «тише», «продолжи» колонка распознаёт без
триггера, локально, стоковой моделью Яндекса (она запускается на нашем
конвейере звука, сеть не нужна). Группы слов включаются и выключаются в панели
(карточка «Быстрые команды»). Когда они работают:

- пока играет музыка: «стоп», «хватит», «пауза», «дальше», «следующий»,
  «назад», «громче», «тише»;
- пока ассистент отвечает голосом: только «стоп», «хватит», «пауза» — он замолкает
  (музыка на паузу не ставится);
- «продолжи» возобновляет музыку, если она играла в последние 15 минут (или
  `voiced` запущен меньше 15 минут назад); если дольше — «Алекса, включи музыку»;
- нужна модель, которую ставит `./setup`. Если её нет, `voiced` всё равно
  запускается, а в панели написано, что быстрые команды выключены.

С моделью эти девять слов принадлежат ей: записать своё слово с таким именем
нельзя, а записанные раньше «стоп», «дальше», «продолжи» и т. п. `voiced` при
первом запуске с моделью удаляет (вместе с записями), чтобы слово не срабатывало
дважды.

Модель берётся с **вашей** колонки и в репозитории не лежит: шаг `./setup`
«Быстрые команды Яндекса» достаёт три файла из прошивки
(`ServicesIosdk.apk`, `assets/quark/spotter_models/command/`) в
`/data/local/tmp/voice/yandex/command/`. Работа проверена на сборке модели
`ru-RU-quasar-commands-29Nov24-08-35-retune-v2-shrd-bt-q16-rt`; с другой `voiced`
пишет предупреждение в лог. Путь меняется флагом `-ycmd-dir`.

**Голос.** Основной путь — встроенный голос Gemini Live (`gemini-3.8-live`),
который сразу отдаёт PCM-аудио и поддерживает перебивание и вызовы инструментов.
Это облачный сервис, он платный. Старый путь с Gemini TTS и запасным Piper
(`ru_RU irina medium`) сохранён для совместимости и аварийного использования. Фразы об ошибках — стоковые звуки Яндекса, которые конвертируются
при установке (в репозитории их нет: `backup/` в `.gitignore`); без них фразу
произнесёт TTS.

**Привязка Spotify** — шаг `./setup` «Spotify Web API». Нужно **своё** приложение
в Spotify for Developers (подойдёт то же, что для Soloist) с redirect URI
`http://127.0.0.1:8765/callback`. Установщик спросит Client ID, откроет браузер
на компьютере для входа (PKCE) и зальёт refresh-токен на колонку
(`/data/local/tmp/voice/spotify.json`, права 600). Нужен Premium (Soloist без
него тоже не работает).

Пока нет: таймеры и будильники (план 2). Gemini Live уже используется как основной
транспорт ассистента; текущий MVP открывает Live-соединение на каждую фразу и сохраняет
локальные VAD-границы, поэтому длительная непрерывная сессия и полноценный barge-in
всего аудиопотока ещё требуют отдельной доработки.

## После запуска

Веб-панель доступна по адресу:

```text
http://<ip-колонки>:8780
```

Через неё можно записать и обучить слова команд, настроить громкость, шаг
кольца, стили индикации и яркость экрана. Карточка «Ассистент»: модель (по
умолчанию как у проверки срабатываний), движок голоса, голос Gemini, город по
умолчанию, статус Spotify и последний запрос.

Ложные срабатывания размечаются частично автоматически. Последние 50
срабатываний хранятся в `<data>/hits` и переживают перезапуск.

- **Проверка через Gemini.** Команда выполняется сразу, а через 10 с запись
  срабатывания (3 с микрофона после эхоподавления) уходит в Gemini
  (по умолчанию `gemini-3.5-flash-lite`, модель выбирается в панели и в `./setup`).
  Модель оценивает вероятность того, что человек сказал
  команду, а не прозвучала песня, ТВ или посторонняя речь. От 70% запись
  помечается «верное», до 30% — «ложное», между ними остаётся без вердикта.
  Разметку, которую вы поставили сами, модель не меняет. Ключ спрашивает
  `./setup` и хранит только на колонке; без ключа проверки нет. На бесплатном
  тарифе Google может использовать эти записи для улучшения своих моделей.
- **Отменённые команды.** Если команду отменили в течение 10 с (пауза → продолжить
  голосом или в приложении, следующий → назад, громче → вернули колёсиком), запись
  подсвечивается. Её достаточно подтвердить, или включить авторазметку таких записей.

Записи, помеченные ложными (вами, после отмены или Gemini), сохраняются как
сложные негативы слова (кроме быстрых команд Яндекса: их модель не обучается,
такая пометка только видна в панели). Когда их набирается 10 с последнего обучения, слово
переобучается само (около минуты); в панели видно «новых N из 10». Кнопка
«Переобучить» запускает обучение сразу.

> В панели сейчас нет аутентификации. Порт `8780` слушает на всех интерфейсах,
> поэтому не выставляйте его в недоверенную сеть и ограничьте доступ firewall'ом
> или локальной сетью.

## Отвязка от Яндекса

Установщик удаляет компоненты Яндекса для пользователя 0 с сохранением данных
(`pm uninstall -k --user 0`), так что всё обратимо:

```sh
adb -s "$ADB_DEVICE" shell -tt 'mysudo -n cmd package install-existing <пакет>'
```

- `com.yandex.io.sdk` — голосовой стек Алисы. Держит микрофон и рисует на кольце
  и экране, поэтому без его удаления проект не работает как задумано. Перед
  удалением установщик копирует из его данных стоковые анимации экрана, которые
  использует `ledd`; в репозиторий они не входят.
- Приложения, которыми колонка с проектом не пользуется: рекламный ID,
  обновлятор, отправка отчётов, скринсейвер, Алиса, Яндекс Музыка, ТВ и видео,
  клавиатуры, магазин, оплата, проверка пульта. Список — `yandexApps` в
  [voice/cmd/setup/steps.go](voice/cmd/setup/steps.go); каждое удалено на Станции
  Макс без потери звука, сети и команд.
- Системные сервисы Яндекса (`tv.services*`, `SystemExtensionService`), лаунчер,
  настройки и мастер первичной настройки остаются: на них опирается система.

Облачный бэкенд Яндекса и серверы обновлений (OTA и их CDN) блокируются на
роутере, а не на колонке; установщик этого не делает.

## Если установка не проходит

Сначала `./setup doctor`: он покажет, какой шаг не в порядке, и подскажет, что
сделать.

- `missing host command` — установите указанную host-зависимость.
- `ANDROID_SDK is required` — задайте `ANDROID_SDK`; на macOS проверьте
  `$HOME/Library/Android/sdk`.
- `missing d8` или `missing Android platform` — установите соответствующие
  Android SDK platform/build-tools.
- `NDK is required` или `aarch64-linux-android28-clang not found` — задайте
  корректный `NDK`.
- `no API key ... not starting` — запустите `./setup`, он спросит ключ.
- `soloist ... not found` — проверьте путь к бинарнику внутри rootfs.
- Мало места на `/data` — кэш Soloist подрезается до 300 МБ раз в 5 минут; если
  место всё равно кончается, `./setup` предложит очистить кэш.
- Нет звука — смотрите `soloist.log`, проверьте PulseAudio rootfs и наличие
  `/dev`/`/dev/pts`, которые монтирует `chroot.sh`.
- Нет веб-панели — проверьте, что `voiced` запущен, и что порт `8780` доступен
  с компьютера.

## Переменные установки

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `ADB_DEVICE` | ADB-адрес колонки | нет; `./setup` спросит или найдёт |
| `ANDROID_SDK` | Android SDK на host | `$HOME/Library/Android/sdk` на macOS |
| `NDK` | Android NDK на host | последняя найденная версия внутри `ANDROID_SDK/ndk` |
| `ANDROID_PLATFORM` | Android SDK platform | `android-28` |
| `ANDROID_BUILD_TOOLS_VERSION` | Версия build-tools/d8 | `34.0.0` |
| `NEG_PYTHON` | Python для negatives dataset | `python3` |
| `HF_ENDPOINT` | Зеркало Hugging Face для negatives (если huggingface.co недоступен), напр. `https://hf-mirror.com` | `https://huggingface.co` |
| `REMOTE_BASE` | Базовый каталог на колонке | `/data/local/tmp` |
| `REMOTE_VOICE_DIR` | Бинарники/данные voice | `$REMOTE_BASE/voice` |
| `REMOTE_SOLOIST_DIR` | Сервис/ключ/rootfs | `$REMOTE_BASE/soloist` |
| `SOLOIST_BASE` | База device-side runtime | `/data/local/tmp/soloist` |
| `VOICE_DIR` | База device-side voice | `/data/local/tmp/voice` |
| `XRAY_BIN` | Путь xray внутри rootfs | `/opt/xray/xray` |

`./setup` работает с путями по умолчанию; `REMOTE_*` понимает только `voice/deploy.sh`.
