# Свои голосовые команды для Станции Макс — дизайн (proof of concept)

Дата: 2026-10-29. Статус: согласован пользователем 2026-10-29.

## Зачем

Станция Макс (Android 9, рут) уже работает как Spotify Connect ресивер: официальный
Spotify Soloist в Debian-chroot, звук через PulseAudio → FIFO → `aaudio_pipe` → audioserver
(всё в `/data/local/tmp/soloist`, исходники в `./soloist`).
Голосом им сейчас управляет «мост», который читает из logcat офлайн-споттер команд Яндекса.

Это сломалось: на новом роутере станция успела получить свежий конфиг от бэкенда Яндекса
(quasar), и споттер Яндекса больше не слушает команды без «Алиса». Полагаться на Яндекс
нельзя — пользователь идёт к максимальной деяндексификации станции.

Цель: собственное распознавание голосовых команд управления музыкой прямо на колонке,
без Яндекса и без сети. Это первый шаг; следующий — своё слово-активатор и двусторонний
голосовой поток с Gemini Live API (бесплатный tier, полноценный live-поток, не STT→TTS).

## Цели (этот PoC)

- Колонка постоянно слушает и выполняет команды **без слова-активатора**, на русском и
  английском:
  - пауза / стоп / pause / stop → пауза
  - продолжи / play → воспроизведение
  - следующий / next → следующий трек
  - назад / previous → предыдущий трек
  - громче / louder → громче
  - тише / quieter → тише
- Работает **под играющую музыку** на нормальной громкости, с того места, откуда
  пользователь обычно говорит.
- Распознавание обучается **на голосе пользователя**: каждую команду он записывает
  ~10–15 раз (так качественнее, это его выбор), запись и обучение — на самой колонке.
- **Единая громкость**: громкость Soloist (ползунок в приложении Spotify), системная/
  аппаратная громкость колонки, физическое колёсико громкости и голосовые «громче/тише» —
  это одна и та же величина, всегда синхронная.
- Быстрые команды (пауза, переключение, громкость) музыку **не глушат** и ничего не
  отвечают: колонка просто выполняет команду.

## Не делаем сейчас (non-goals)

- Кольцо подсветки и экран — позже, по наработкам пользователя (его отдельные репозитории).
- Слово-активатор и Gemini Live — только задел в архитектуре (см. ниже), не реализация.
- Команды от людей, которые не записали свой голос.
- Глубокое удаление Яндекса из системы (это следующий этап деяндексификации).

## Анти-цели (провал, даже если «работает»)

- Музыка сама по себе вызывает команды: больше пары ложных срабатываний в час — провал.
- Сломан рут, ADB или автозагрузка (`/data/local/tmp/myscript-max.sh` → `soloist/start.sh`).
- Сломан текущий Spotify-ресивер.

## Что выяснено на железе (факты, проверено спайками 2026-10-29)

- **Микрофон эксклюзивен**: в Android 9 его получает тот, кто открыл первым. Пока работает
  `com.yandex.io.sdk`, наша запись — нули. `am force-stop` его не берёт, `pm disable`
  запрещён («protected package»); работает `busybox kill -9`, после чего процесс через
  пару секунд перезапускается сам, но если микрофон к этому моменту открыли мы — он
  остаётся нашим (проверено: Яндекс перезапустился посреди нашей записи, звук не пропал).
- **Формат, как у Яндекса**: источник `MIC` (1), 48 кГц, PCM16, **16 каналов по индексной
  маске** `0xffff`. AAudio 16 каналов открыть не даёт (`ILLEGAL_ARGUMENT`); моно/16 кГц
  через AAudio даёт кашу (Android сводит/пересэмплирует неправильно). Работает Java
  `android.media.AudioRecord` с `setChannelIndexMask(0xffff)`.
- Java запускается без APK: `CLASSPATH=x.dex app_process /system/bin Main` от root.
  Нужны две вещи: переменные окружения из обычного adb shell (`BOOTCLASSPATH`,
  `ANDROID_ROOT`, … — mysudo даёт почти пустое окружение; готово в
  `/data/local/tmp/soloist/javaenv.sh`) и `ActivityThread.systemMain()` перед созданием
  `AudioRecord` (иначе нативная часть падает на null opPackageName). Рабочий спайк:
  `/private/tmp/.../scratchpad/micrec/MicRec.java` (перенести в проект).
- **Раскладка каналов** (по записи под музыку + голос; на слух подтвердил пользователь):
  - 0–10 — микрофоны; голос лучше всего в 3 и 4 (при той позиции говорящего), хуже в 0, 1.
    Каналы 4/6/8 и 5/7/9/10 почти копии друг друга (корреляция 0,97–1,0).
  - **11–14 — копия того, что играет динамик** (эталон для эхоподавления): 11=13, 12=14,
    две пары = L/R.
  - 15 — пусто.
  - Сырые микрофоны тихие (~−50 dBFS), нужно усиление.
- Эхоподавление Яндекса (`YandexVQE`) — это аудиоэффект, который вешает на свою сессию
  сам `io.sdk` (UUID `37800c12-ba40-11ec-8422-0242ac120002`), а не HAL. Мы его не используем.
- **Кнопка Алисы**: `/dev/input/event0` (`gpio_keypad`, `KEY_VOICECOMMAND`=582).
  **Колёсико громкости**: `/dev/input/event2` (`rotary-volume`, `KEY_PAGEUP/KEY_PAGEDOWN`).
  Оба сейчас обрабатывает `io.sdk`; аппаратную громкость тоже ставит он
  (`audio_hw_primary: Set hardvol volume: N`).
- Soloist: WebSocket API на `127.0.0.1:9771` (`soloist ctl -w ...`: play/pause/next/prev/
  volume, события). Устройство в Spotify — «Яндекс Станция».
- Рут-оболочка: только с TTY (`adb shell -tt 'mysudo -n …'`); вложенные кавычки через
  mysudo ломаются — запускать скрипты файлами. `kill`/`pkill` не работают, только
  `busybox kill -9`. Контекст `u:r:kernel` в permissive.

## Решения пользователя

- Распознавание — **подход station-wakeword** (`../station-wakeword`):
  openWakeWord-фронтенд и speech embedding на Go + маленький классификатор на каждое
  слово, обучаемый на станции по записям пользователя. Отдельная модель на каждый
  вариант слова/языка, несколько моделей → одно действие.
- **Микрофон забираем у Яндекса**, процесс Яндекса гасим. «Алиса» и её офлайн-команды
  перестанут работать — это принято.
- **Громкость едина** для Soloist, системы, колёсика и голоса (см. цели).
- Никакой обратной связи на быстрые команды пока не нужно.
- Позже: после слова-активатора музыка **приглушается**, как в оригинальной станции
  (для быстрых команд — нет).
- LLM в будущем — **Gemini Live API** (live-поток аудио в обе стороны).
- **Ложные срабатывания от речи и ТВ** («стоп», «назад», «next» в разговоре) пока
  допустимы, если редкие; анти-цель про «пару в час» относится к самой музыке.
  Дообучение на разговорах/ТВ, распознавание только своего голоса или префикс перед
  командой — потом, если это станет реальной проблемой.
- **Всё, что делает `io.sdk`, кроме микрофона, можно потерять**: Алису, кнопки, Bluetooth,
  подсветку/экран, системные звуки, обновления. Нужен только ADB (и рут, автозагрузка,
  Spotify). Для всего остального потом будут свои сервисы. Кнопка выключения микрофона
  полностью аппаратная (работает даже вне системы) — её не трогаем и не обрабатываем.
  OTA и так заблокирована на роутере (серверы OTA и CDN → 0.0.0.0).

## Архитектура (как задумано)

```
AudioRecord (MIC, 48 кГц, 16 кан.)  ← Java-хелпер через app_process (root)
        │ сырые кадры по unix-сокету/pipe
        ▼
voice-daemon (Go, статический arm64, работает вне chroot)
  1. каналы 0–10 → микрофоны, 11–14 → эталон (что играет динамик)
  2. эхоподавление: вычесть эталон из микрофонов
  3. свести микрофоны в один чистый сигнал, усилить, 48→16 кГц
  4. KWS: общий embedding + модели слов (код station-wakeword)
  5. действие: Soloist ws API / громкость
  + веб-UI записи и обучения слов (из station-wakeword), открывается с телефона
  + колёсико громкости (/dev/input/event2) и единая громкость
  + задел: тот же чистый 16 кГц поток позже пойдёт в слово-активатор и Gemini Live
```

Запускается тем же супервизором, что и остальное (`soloist-service.sh`); при старте
гасит `io.sdk` (`busybox kill -9`) и сразу открывает микрофон; если микрофон не
открылся/даёт нули — лог и повтор. Старый `voice-bridge.sh` (logcat) убирается.

## Оставлено строителю (решай сам, но пометь как своё решение)

- Как именно Java-хелпер отдаёт звук демону (pipe, unix-сокет) и кто из них главный.
- Алгоритм эхоподавления (WebRTC AEC3/APM, speexdsp, свой NLMS) — нужен такой, что
  собирается под arm64 и укладывается по CPU вместе с KWS. Эталон 48 кГц стерео,
  задержка эталон→микрофон неизвестна — измерить.
- Как сводить микрофоны (сумма лучших каналов, delay-and-sum, адаптивный выбор).
  Позиция говорящего меняется — один фиксированный «лучший» канал не годится.
- Как гасить `io.sdk` надёжно в рамках PoC (kill при старте + удержание микрофона —
  минимум; если он мешает иначе — разобраться). Сохранять его функции не нужно,
  главное — чтобы он не воевал с нами за микрофон, колёсико и громкость и не ломал ADB.
- Как ставить аппаратную громкость без `io.sdk` (через Android `AudioManager`/
  `media volume`, через параметры HAL — проверить, что реально меняет громкость
  на этой станции) и как связать её с громкостью Soloist так, чтобы громкость не
  применялась дважды (Soloist может уже ослаблять звук программно — проверить).
- Форк/вынос кода из station-wakeword: что брать как есть (kws, enroll, UI), что
  менять (источник звука вместо `yio_audio`, действие вместо «разбудить Алису»).
  Лицензии: `negatives.bin` — CC BY-NC-SA (некоммерческое использование, ок для себя).
- Порт веб-UI (у station-wakeword 8780), структура каталогов в `/data/local/tmp/`.
- Нагрузка: ~12 моделей одновременно, Cortex-A53; проверить, что CPU хватает
  вместе с Soloist и PulseAudio.

## Решения агента-проектировщика (не пользователя; можно переиграть)

- **Набор команд**: шесть действий из целей; синонимы из старого моста тоже идут
  отдельными словами («хватит» → пауза, «играй» → play, «дальше» → next). В веб-UI у
  каждого слова выбирается действие из фиксированного списка, так что пользователь
  может добавить свою фразу без правки кода.
- **Главная громкость — системная/аппаратная громкость колонки**, она одна на всё, что
  колонка играет. Soloist её зеркалит: событие громкости из Spotify → ставим
  аппаратную; колёсико/голос → ставим аппаратную и отправляем то же значение в Soloist,
  чтобы ползунок в приложении совпадал. Программное ослабление в самом Soloist не должно
  складываться с аппаратным (как именно — решает строитель). После перезагрузки
  восстанавливается последняя громкость.
- **Испытания**: громкость музыки «обычная» = **15 %** (решение пользователя: ночь,
  многоквартирный дом; это же громкость по умолчанию при старте, если сохранённой нет);
  проверяет пользователь вживую в комнате. Строитель
  дополнительно сохраняет записи сессий (16 каналов) для повторного прогона на маке,
  чтобы подбирать эхоподавление и пороги без пользователя.
- **Веб-UI без пароля**, слушает в локальной сети — для PoC в домашней сети этого
  достаточно; записи и срабатывания хранятся только на колонке.

## Критерии готовности PoC

- После перезагрузки колонки всё поднимается само; Spotify играет как раньше.
- С телефона открывается страница, на ней записаны и обучены команды пользователя.
- Под музыку на обычной громкости каждая команда срабатывает с обычного места говорящего
  (ориентир: 9 из 10 попыток), ложных срабатываний от музыки — не больше пары в час.
- Громкость: ползунок Spotify, колёсико и «громче/тише» двигают одну и ту же громкость,
  и ползунок в приложении показывает актуальное значение.
