# ИИ-ассистент на Станции Макс — дизайн

Дата: 2026-10-31. Статус: согласован пользователем 2026-10-31.

## Зачем

Колонка уже умеет быстрые команды без облака (пауза, дальше, громкость) на своём KWS в
`voiced`. Пользователь хочет, чтобы она работала **как обычная умная колонка**: сказал
слово-триггер, потом свободную фразу («лайкни трек», «включи The Weeknd», «погода в
Праге», «поставь таймер на 10 минут»), колонка выполнила и ответила голосом. Плюс
отдельный режим непрерывного разговора через Gemini Live, потому что он дешевле и
живее для диалога. **По умолчанию колонка работает как агент**, а не как собеседник.

Облако для ИИ-части пользователь принимает: локально работают быстрые команды, ИИ
по понятным причинам требует сети. README нужно переписать соответственно.

## Как это устроено у Яндекса (проверено на прошивке 2026-10-31)

- Голосовой стек живёт в `/system/priv-app/ServicesIosdk/ServicesIosdk.apk`
  (`com.yandex.io.sdk`, 150 МБ, у нас удалён для user 0). Внутри споттеры
  «Алиса», «Яндекс», «Ясмина» (`.nnet`, закрытый движок), модель распознавания голоса
  по говорящему (`ecapa-tdnn`, tflite), анимации экрана и ~30 заранее записанных фраз
  на ru-RU (`assets/quark/sounds/...`).
- **Модели синтеза речи на устройстве нет.** `libquasar_daemons.so` содержит только
  клиент uniproxy (облачный шлюз) и директиву `TtsSpeak`: готовый звук ответа
  приходит из облака. `YandexTvAlice.apk` — UI и копия споттера, TTS тоже нет.
- Вывод: голос Алисы локально взять нельзя. Из стока берём только записанные фразы и
  звуки (ошибки, таймер, будильник). Часть уже лежит в `backup/sounds` и
  `/data/local/tmp/voice/assets`. Yandex SpeechKit не используем: Яндекс сознательно
  отрезан на роутере.

## Цели

1. **Режим агента (по умолчанию).** Слово-триггер, потом фраза, потом действие и короткий
   голосовой ответ. Список инструментов ниже.
2. **Слово-триггер настраивается в существующей панели :8780.** Это любое записанное
   слово, которому назначено новое действие «ассистент» (рядом с pause/play/...).
   Отдельной механики нет: тот же enroll, обучение, autotrain.
3. **Follow-up без триггера.** После ответа агента колонка ~5 с слушает дальше без
   триггера, как Алиса при уточнениях.
4. **TTS:** Piper локально, на колонке. Сразу закладываем интерфейс под второй движок,
   **Gemini TTS**, с выбором в панели. Ошибки и сигналы озвучиваются стоковыми звуками
   Яндекса.
5. **Режим разговора (Gemini Live).** Вход двумя путями: фразой агенту («давай
   поболтаем», модель вызывает `start_conversation`) **и** отдельным словом из панели
   (новое действие «разговор»). Непрерывный двусторонний аудиопоток, перебивание,
   те же инструменты. Выход: «хватит»/«пока» (`end_conversation`), тишина или кнопка.
6. **Индикация на кольце/экране** через `ledd`: слушаю, думаю, говорю, в разговоре,
   ошибка, таймер.

## Инструменты (общие для агента и Live)

| Инструмент | Как |
|---|---|
| play / pause / next / prev / громкость | Soloist WS (`voice/internal/soloist`), громкость через единую громкость `voiced` |
| «включи <артист/трек/альбом/плейлист>» | Spotify Web API: поиск, затем запуск на устройстве Soloist |
| «лайкни трек» / «убери лайк» | Spotify Web API: сохранить текущий трек в библиотеку или убрать |
| «что играет» | Soloist или Web API, ответ голосом |
| таймер, будильник (поставить, сколько осталось, отменить) | локально в `voiced`, переживают перезапуск, звенят стоковыми звуками, видны на кольце |
| погода | Open-Meteo (без ключа), город по умолчанию задаётся в панели |
| время и дата | локально |
| общие вопросы | Google Search grounding внутри Gemini |
| начать / закончить разговор | переход в режим Live и обратно |

Spotify Web API требует однократной OAuth-авторизации пользователя, кнопка в панели.
Токен обновления хранится на колонке. Client ID/secret берутся из Spotify developer
app пользователя. Он у пользователя есть, потому что Soloist без него не работает, и
аккаунт у пользователя с Premium (Soloist иначе тоже не работает), так что ограничения
development mode не мешают. Подойдёт ли тот же app или нужен второй — проверяет
строитель.

## Поток в режиме агента

1. KWS ловит слово с действием «ассистент». Музыка приглушается (duck), кольцо
   показывает «слушаю».
2. Запись чистого 16 кГц потока (после AEC) до конца фразы по VAD. Предел ~10 с, тайм-аут
   ожидания начала речи ~4 с.
3. Аудио вместе с системным промптом, инструментами и короткой историей
   (последние реплики в пределах follow-up) уходит в Gemini `generateContent`.
   Модель выбирается в панели, по умолчанию та же, что для «судьи».
4. Модель возвращает вызовы инструментов и/или текст. `voiced` выполняет вызовы,
   результаты отдаёт модели и получает финальную фразу.
5. Фраза озвучивается выбранным TTS. Музыка возвращается к прежней громкости.
6. Окно follow-up ~5 с: речь в нём идёт в тот же диалог без триггера.

Если модель решила, что запроса не было (триггер ложно сработал на музыку/ТВ), колонка
молча возвращается в обычный режим, а клип сохраняется как ложное срабатывание слова
(как сейчас делает «судья»).

## Режим разговора (Gemini Live)

- Сессия Live (WebSocket), вход — 16 кГц PCM после AEC непрерывно, выход — аудио
  голосом Gemini, проигрывается сразу.
- Музыка на время разговора ставится на паузу и возобновляется после выхода.
- Перебивание: Live сам определяет речь пользователя и обрывает ответ, `voiced` сразу
  глушит воспроизведение остатка.
- Выход по `end_conversation`, ~20 с тишины, кнопке на колонке (какой — решает строитель).
- Лимит длительности сессии: переподключение с возобновлением контекста (session
  resumption / сжатие контекста Live), чтобы длинный разговор не обрывался.
- Кольцо: отдельное состояние «в разговоре».

## Ограничения

- Всё работает внутри `voiced` (Go, Android, root) и chroot Debian, где уже живёт
  Soloist. Учитывать особенности `mysudo` и окружения (см. README).
- Gemini недоступен с российского IP напрямую: трафик идёт через прокси, как у «судьи»
  (роутер или Xray на колонке, выбирается в `./setup`). Spotify Web API — так же.
- Ключ Gemini тот же, что у «судьи».
- Быстрые команды работают как раньше: локально, без триггера, без ответа. Ассистент
  не должен добавлять им задержку.
- Пока колонка говорит, AEC видит её голос в опорных каналах (TTS играет через тот же
  тракт PulseAudio → aaudio_pipe), чтобы не сработать на собственный ответ.
- Место на `/data`: Piper с одним русским голосом укладывается в ~100 МБ. `./setup`
  учитывает его в проверке свободного места.

## Не делаем (non-goals)

- Локальное распознавание свободной речи (Whisper и т.п.): свободные фразы понимает
  Gemini по аудио.
- Голос Алисы или его подделка.
- Яндекс SpeechKit и любые сервисы Яндекса.
- Умный дом, звонки, напоминания по календарю, несколько пользователей.

## Анти-цели (провал, даже если «работает»)

- Сломаны или замедлены быстрые команды, Spotify-ресивер, рут, ADB или автозагрузка.
- Ассистент регулярно срабатывает сам на музыку или ТВ и что-то делает или говорит.
- Колонка отвечает на собственную речь (зацикливание в follow-up или Live).
- Без сети колонка молчит или зависает: ошибка должна прозвучать стоковой фразой, а
  быстрые команды продолжают работать.
- Ключи и токены утекают в логи или в ответы панели.

## Решения пользователя

- Облако для ИИ — нормально; README перепишем.
- TTS: Piper сейчас, задел на Gemini TTS.
- Слово-триггер — через существующую панель (действие у записанного слова).
- В разговор входим и фразой агенту, и своим словом.
- По умолчанию — агент, Live — отдельный режим.
- Поиск, запуск и лайки идут через Spotify Web API (developer app и Premium есть).

## Решения проектировщика (не пользователя; можно переиграть)

- Распознавание свободной фразы делает Gemini по аудио, без отдельного STT.
- Ложный триггер, на котором модель не услышала запроса, — тихая отмена плюс клип в
  ложные срабатывания для autotrain.
- Follow-up ~5 с, тишина для выхода из Live ~20 с.
- Музыка: duck в режиме агента, пауза в Live.
- Погода — Open-Meteo, город по умолчанию в панели.
- Таймеры и будильники — локальные, в `voiced`.
- Модель агента по умолчанию — та же, что для «судьи»; модель Live — отдельный выбор
  в панели.
- Gemini TTS делаем рабочим движком (это один REST-вызов), но по умолчанию выключен;
  выбирается в панели. Критерий готовности — переключение в панели меняет голос.
- Задержка агента: цель — не больше ~3 с от конца фразы до начала ответа на простых
  командах. Ради неё ответ модели стримится, а TTS начинает говорить с первого
  предложения.
- Будильники: разовые на время и повторяющиеся по дням недели, без «отложить».
  Звонок останавливается **локально, без сети**: любым записанным словом (триггером или
  быстрой командой), колёсиком/кнопкой на колонке, сам через 5 минут. Звонок важнее
  всего: глушит музыку, прерывает речь колонки и ставит Live на паузу.

## Оставлено строителю (решай сам, но пометь как своё решение)

- Где запускать Piper: нативно на Android или в chroot Debian (glibc + onnxruntime), и
  как держать его тёплым (резидентный процесс), чтобы первая фраза не грузила модель.
- Как TTS и Live-аудио попадают в звуковой тракт (отдельный sink-input PulseAudio в
  chroot, рядом с Soloist, или иначе), лишь бы AEC видел это в опорных каналах.
- Выбор русского голоса Piper.
- Тот же developer app, что у Soloist, или отдельный client ID для Web API. Схема OAuth
  (redirect через панель на :8780; учесть, что Spotify требует https или loopback в
  redirect URI).
- Формат истории диалога, системный промпт, язык ответов (по языку запроса).
- Какая кнопка на колонке завершает Live.
- Структура пакетов (например `internal/assistant`, `internal/tts`, `internal/live`,
  `internal/spotifyapi`), API панели, раскладка конфигов и секретов.
- Анимации кольца/экрана для новых состояний в стиле существующих стилей `ledd`.
- Шаги `./setup` и `./setup doctor` для Piper, OAuth и проверки доступности Gemini.

## Критерии готовности

- «<триггер>, лайкни трек» — трек в «Любимых», короткое голосовое подтверждение.
- «<триггер>, включи The Weeknd» — на колонке играет The Weeknd.
- «<триггер>, погода в Праге» — голосом текущая погода и прогноз на сегодня.
- «<триггер>, таймер на 1 минуту» — через минуту звенит, на кольце виден отсчёт; таймер
  переживает перезапуск `voiced`.
- Follow-up: «<триггер>, включи Daft Punk» → «а теперь погромче» без триггера.
- «<триггер>, давай поболтаем» — живой диалог с перебиванием, «хватит» — возврат к
  музыке. То же своим словом из панели.
- Без интернета: стоковая фраза об ошибке; быстрые команды работают, звенящий
  будильник останавливается.
- Будильник на 7:30 по будням звенит и выключается колёсиком.
- Переключение TTS на Gemini в панели меняет голос ответов.
- Быстрые команды по задержке не хуже, чем до изменений.
